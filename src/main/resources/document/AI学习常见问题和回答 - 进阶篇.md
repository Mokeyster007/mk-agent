# AI 学习常见问题和回答 - 进阶篇
#### 什么是大语言模型（LLM）？它是如何工作的？
大语言模型（Large Language Model，LLM）是基于海量文本数据预训练、依靠 Transformer 架构、具备上下文理解与文本生成能力的巨型参数模型。它的核心工作方式可以概括为"预测下一个词"：模型读取前文后，计算下一个词（Token）的概率分布，选出最合适的词，再把它拼回输入继续预测，如此循环生成完整回答。LLM 的能力来自两个阶段：预训练阶段，在互联网规模的语料上学习语言规律与世界知识；对齐阶段，通过指令微调（SFT）和基于人类反馈的强化学习（RLHF）让模型"懂规矩"——理解指令、拒绝有害请求、输出符合人类偏好的回答。理解了这个框架，你就能解释很多现象：模型知识会过时（预训练有截止日期）、会编造（生成本质是概率补全而非查证）、有上下文长度限制（一次能处理的 Token 数有限）。
推荐资源：[AI 智能问答系统：从底层到实践](https://juejin.cn/post/7626706420446593059)，系统梳理了从文本、向量、神经网络到 Transformer 与 LLM 的完整知识分层。

#### Transformer 的核心原理是什么？为什么它如此重要？
Transformer 是 2017 年 Google 提出的神经网络架构，核心机制是自注意力（Self-Attention），它让模型在处理一个词时能够"同时关注"输入序列中所有其他词，从而直接捕捉任意距离的上下文依赖关系。在它之前，RNN 必须逐词顺序处理，既慢又容易丢失长距离信息；Transformer 的并行计算特性使得在超大规模数据上训练成为可能，这是现代大模型诞生的前提。结构上，Transformer 由编码器（Encoder，擅长理解，如早期的 BERT）和解码器（Decoder，擅长生成，如 GPT 系列）两大模块组成，如今主流大语言模型普遍采用解码器结构。学习建议：先理解"注意力是加权求和"这个直觉——每个词根据与周围词的相关性获得权重，再看多头注意力与位置编码的设计动机，最后结合一个简化实现（如 nanoGPT）读代码，不必一开始就推导全部公式。
推荐资源：[Hugging Face 开源社区](https://huggingface.co/)，提供大量 Transformer 模型与可视化教程，是理解与动手实践结合的最佳场所。

#### RAG 是什么？它解决了大模型的哪些问题？
RAG（Retrieval-Augmented Generation，检索增强生成）是在大模型回答之前，先从外部知识库检索相关资料，再让模型基于资料生成答案的技术方案。它针对大模型的四个先天缺陷：一是幻觉，模型不懂的问题也敢编，RAG 提供事实依据降低瞎编概率；二是知识过时，模型的知识定格在训练截止日，RAG 可接入最新资料；三是缺乏私有知识，企业内部文档模型从未学过，RAG 让私有数据无需参与训练即可被问答使用，规避了数据安全风险；四是上下文长度有限，RAG 只把最相关的片段塞进提示词，成本更低。标准链路是：文档切分为小块 → 通过嵌入模型转为向量并存入向量数据库 → 用户提问同样转为向量 → 检索语义最相近的若干片段 → 拼入提示词交给大模型生成答案。一句话记忆：RAG = 检索技术 + LLM 提示。
推荐资源：[RAG 和 Embedding 技术解析：从理论到实践](https://www.cnblogs.com/yudanqu/p/22435830)，从原理到代码完整讲解 RAG 三大核心（知识库、检索、大模型）与 Embedding 的关系。

#### 什么是 Embedding 和向量数据库？学习时需要掌握到什么程度？
Embedding（嵌入）是把文本、图片等非结构化数据映射为一串数字向量的技术：语义越接近的内容，向量在空间中的距离越近。比如"学习人工智能"与"入门机器学习"的向量会很接近，而与"今晚吃什么"距离较远。向量数据库（如 pgvector、Milvus、Elasticsearch 的向量索引）就是专门存储和检索这些向量的系统，支持"找出与查询向量最相似的 TopK 条记录"，这正是 RAG 检索环节的基础设施。学习时建议掌握三个层次：概念层——理解"语义相似度 = 向量距离/余弦相似度"；使用层——会用一种嵌入模型（如 DashScope 的 text-embedding）把文本转向量，并用一个向量库完成存储与检索；调优层——理解分块大小、维度匹配、混合检索（向量 + 关键词）对召回质量的影响。应用开发岗位重点在概念层与使用层，无需深入索引的数学推导。
推荐资源：[Spring AI 官方文档·Vector Databases](https://docs.spring.io/spring-ai/reference/api/vectordbs.html)，覆盖 pgvector、Milvus 等主流向量库的接入方式，适合 Java 开发者。

#### 微调和 RAG 应该如何选择？
两者都是让大模型"懂你业务"的手段，但适用场景不同。微调（Fine-tuning）是在领域数据上继续训练模型、改变其权重，适合改变模型的行为风格，比如统一输出语气、掌握特定任务格式、学会领域"说话方式"；但成本高、周期长，且难以频繁更新知识。RAG 不改模型权重，把知识放在外部库中随用随查，适合知识密集型问答（企业知识库、客服、合同审查），优势是知识可随时更新、可追溯来源、成本低。决策口诀：知识更新频繁、需要引用出处，选 RAG；要固化某种输出风格或专项能力，选微调；很多生产系统两者结合——微调负责"像专家一样说话"，RAG 负责"知道最新的事实"。学习路线上建议先掌握 RAG（落地快、需求大），再根据工作方向决定是否深入微调。
推荐资源：[RAG 全景——从原理到实践](https://blog.csdn.net/ggggjatihc/article/details/164067317)，详细对比了 RAG 与微调、长上下文的选型决策，并给出完整落地路径。
