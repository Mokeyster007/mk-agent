# 音乐平台接入：官方能力证据表

> 本轮结论先行：**没有接入任何真实音乐平台**。仓库里只有两个明确标注
> 「模拟」的只读适配器（`demo-alpha` / `demo-beta`），它们不发网络请求、
> 没有 OAuth、没有凭据。任何"已接网易云 / QQ 音乐"的说法在本轮都不成立。

这份表的目的不是"选一个平台接上"，而是把**证据与缺口**摊开：
哪些能力有官方通道、哪些根本没有面向第三方的公开接口、哪些必须商务合作。
没有证据的格子留空并标注「未实测」，不用推断填空。

状态图例：

| 标记 | 含义 |
| --- | --- |
| **已实测** | 本仓库内跑过真实请求 / 真实回调 |
| **未实测** | 有官方文档通道，但本轮没有凭据，未发过真实请求 |
| **不开放** | 官方没有面向第三方开发者的公开通道 |
| **需商务合作** | 只有企业/内容合作方才能获得权限，个人开发者不可申请 |

**说明**

1. 上表的"未实测"不是"应该可以"，而是"官方文档里有这条通道，但本项目没有凭据，
   一次真实请求都没发过"。接入前必须逐条复验文档与条款（平台条款会变）。
2. 站内播放这一列全部不是"接个 `<audio>` 就行"：Spotify / Apple / Tidal
   都要求平台自己的 SDK 与 DRM；Deezer 多数曲目只有预览；SoundCloud 明确禁止代理。
   这与本项目"不代理第三方流"的边界一致——所以本轮**没有**做第三方播放。
3. "读得到"与"能存、能分析、能发给模型"是三件独立的事。上表后三列全部是限制项，
   没有一格可以默认放行。

## 2. 本轮实际交付的适配器

| 适配器 | 类型 | 能力 | 是否发网络请求 | 数据来源 |
| --- | --- | --- | --- | --- |
| `demo-alpha` | 模拟 | 目录搜索 / 读歌单 / 读喜欢 / 读最近播放 | 否 | 代码内固定数据 |
| `demo-beta` | 模拟 | 同上 | 否 | 代码内固定数据 |

- 两者**都没有** `PLAYBACK` 能力：外部曲目在本页不可播放（`playable=false`），
  原因写在 `playableReason` 里，界面直接展示。
- 两者刻意包含同名歌曲（《夜航星》，同歌手），用于验证聚合层**不按歌名去重**。
- 界面在所有模拟来源旁标注「模拟」，页脚写明"没有连接任何真实平台"。

## 3. 真实平台绑定的前置条件（本轮未满足）

### 3.1 可信身份

当前身份来自 `X-User-Id` 请求头，可以被任意伪造。用它作为真实平台连接的归属，
等于允许把别人的音乐账号挂到伪造的身份下。因此：

- `mkagent.providers.trusted-identity` 默认 `false`；
- 真实来源绑定一律返回 `409 IDENTITY_NOT_TRUSTED`；
- 只有模拟来源可以连接（没有凭据、没有外部账号，最坏情况是看到假数据且已标注）。

### 3.2 OAuth 回调（设计，未实现）

真实平台接入时必须补齐以下链路。这里记录设计，避免下一轮重新讨论：

| 环节 | 要求 |
| --- | --- |
| 依赖 | `spring-boot-starter-oauth2-client`（本轮**未**引入：它会改变全局安全链，在没有真实凭据时只会增加风险面） |
| 发起 | 服务端生成 `state`（随机、一次性、与服务端会话/用户绑定），PKCE 的 `code_verifier` 只存服务端 |
| 回调 | 校验 `state` 与发起用户/发起连接一致；`state` 不匹配直接拒绝，不创建连接 |
| 令牌 | access/refresh token 只进外部密钥存储，连接表只存 `credential_ref` |
| 刷新 | 过期前刷新；刷新失败把连接标为 `EXPIRED`，界面提示重新授权 |
| 解绑 | 删除连接 + 撤销令牌（平台支持时）；本地不保留任何令牌副本 |
| 范围 | 只申请 `read:*`，**不申请**任何写范围 |

当前 `ProviderBindingGuard` 的最后一道分支就是为这条链路留的：
即使身份可信、凭据已配置，也会返回 `501 PROVIDER_OAUTH_NOT_IMPLEMENTED`，
不会写一条"已连接但没有令牌"的假记录。

## 4. 数据边界（本轮已生效）

| 边界 | 实现位置 | 说明 |
| --- | --- | --- |
| 凭据不进前端 | `ProviderController.ConnectionView` | 连接视图不含 `credentialRef`，更不含令牌 |
| 凭据不进日志 | `ProviderAggregationService` | 异常只记类型，不记 message（可能含 URL/token） |
| 第三方数据不进模型 | `ProviderCapabilities.shareWithModel()` | 恒为 `false`，且不是构造参数 |
| 外部 ID 不填本地 songId | `ProviderTrack` | 没有 `localSongId` 字段；不自动导入曲库 |
| 不代理第三方流 | `MusicProviderAdapter` | 接口里没有"取播放地址"方法 |
| 不写回平台 | `ProviderCapability` | 枚举里没有写能力，本轮也不申请写范围 |

## 5. 给下一轮的 TrackRef 契约

跨来源引用必须能唯一定位一首歌，且不依赖歌名。建议沿用本轮的字段：

```json
{
  "provider": "spotify",
  "providerTrackId": "6rqhFgbbKwnb9MLmUQDhG6",
  "title": "夜航星",
  "artist": "林晚",
  "album": "夜航",
  "version": null,
  "durationSeconds": 241,
  "playable": false,
  "playableReason": "该来源不支持站内播放"
}
```

规则：

1. 身份是 `provider + providerTrackId`；**禁止**按 `title + artist` 去重。
2. 不携带任何地址、令牌、用户标识。
3. `playable` 只描述"本页能不能放"，不代表平台允许下载或转存。
4. 想让它变成可播的本地曲目，必须先在本地曲库建立音源映射（另一条链路，需单独授权）。

## 6. 复验清单（接入真实平台前必须逐项确认）

- [ ] 平台开发者条款是否允许"展示第三方来源的曲目元数据"
- [ ] 是否允许把元数据缓存到自有数据库、缓存多久
- [ ] 是否允许把元数据发送给第三方大模型（默认按不允许处理）
- [ ] 站内播放是否必须使用平台 SDK / DRM，能否在浏览器中实现
- [ ] 令牌存储与刷新方案是否满足平台的安全要求
- [ ] 解绑时是否需要调用平台撤销接口
- [ ] 品牌与署名要求（图标、名称、免责声明）
